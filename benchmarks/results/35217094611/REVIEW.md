耗时合计包括每个独立任务的模型冷启动；12 个任务并行运行，并非用户实际等待近两小时。
不同任务可能分配 AMD EPYC 7763、9V74 或 Intel Xeon，不能把 7.2 倍当作固定硬件性能结论。
开启组的 3 个未完成样例不是“已经答完但答错”；也不能只挑完成的 3 条宣称 100% 准确率。
所有 12 个任务均完成并保存报告；任务 success 不等于答案合格。

## 设置和前两轮

最终对照两组只改变 think 开关：
- 同一 Q8_0 模型摘要 441ec31e4d2aedceb97dd834b036db104d943fbe3dbc1e5c8ac95eeaa9141c77，Ollama 0.34.1，CPU 4 线程。
- 同一六份公告、提示词、JSON schema、金标准和评分器；schema 放入提示词，均不使用原生 format 约束。
- temperature=1、top_p=.95、top_k=20、min_p=0、presence_penalty=1.5、repeat_penalty=1、seed=42。
- num_ctx=8192、num_predict=4096、每条 timeout=1800 秒。采样参数依据 [Qwen 官方建议](https://huggingface.co/Qwen/Qwen3.5-9B#best-practices)；该输出预算仍低于官方建议的 32768 tokens，属于受限 CPU 实用性测试，不能当作模型能力上限。
- 11 项评分和请求隔离测试在 CI 通过；核对了所有样例的输入 hash、金标准、模型摘要、两组配置及最终原始 JSON 与评分记录的一致性。
- 记录最终 response 和独立 thinking 字段，只对最终答案评分，没有截取思考中的答案充当成功，也没有修复重试或规则兜底计分。

先后保留了三轮，避免隐藏失败：
1. [原生 schema + 思考的接口探测](../35215503163/REVIEW.md)：6/6 最终答案为空，JSON 出现在 thinking 字段，不作为能力比较。
2. [temperature=0 / 2048-token 对照](../35215827052/REVIEW.md)：开启组 6/6 截断；关闭组字段 3/6。
3. 本轮官方思考采样参数、4096-token 对照：开启组交付 3/6，关闭组字段 4/6。跨轮同时改变了采样和预算，不能把跨轮变化单独归因于某一参数。

资源方面，开启组采样最大 Ollama 进程 RSS 合计约 11.58 GiB，系统最低可用约 3.07 GiB，最大已用 swap 84 KiB；失败原因是输出 token 耗尽，未出现请求超时。RSS 合计可能重复计算共享页面，5 秒采样不等于精确峰值。

这只是六个手选样例、单个 seed 的实验，不能推断普遍准确率。完成的三个样例含两份同一公司的公告，困难阶段样例仍未交付。生产保持 Q4 事实 ID 选择方式，不将思考实验用于自动更新分拆名称、状态或日期。
